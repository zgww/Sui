# 测点档案 HTTP 容量复测（ARM64）

环境：192.168.6.88，隔离容器 `fms-point-archive-test-env`。未访问生产数据或真实设备。

## 方法与结论

运行 `python -m scripts.validate_point_archive_capacity`。使用既有 `make_rows(10000)`，10000 测点、100 设备、10 间隔、50 条分页；交替查询全站和单设备，均包含名称“油温”和 `bound=false`，断言总数分别为10000/100，页面均50条。没有缩短字段或替换查询。

已改为真实 loopback TCP Uvicorn；Linux 使用独立服务端进程，10个持久 HTTP 客户端；先10次预热，再100次测量。鉴权角色替换为 engineer；SQLite 使用临时文件和真实查询，绑定表为空。客户端与服务端仍共享物理主机 CPU，结果不是外部网络或生产鉴权耗时。

**初次优化前结果未达到方案建议的 p95 ≤100 ms，重载 ≤2 s 也未稳定达到。优化后的最终结果已达稳定阶段目标，见下文。** 内存目标128 MiB以内通过本次合成样本检查。功能测试通过不代表此性能门槛通过。

| 指标 | 独立服务端进程结果 |
|---|---:|
| API 中位耗时 | 139.06 ms |
| API p95 | 185.62 ms |
| API 最大耗时 | 209.88 ms |
| 预热批次最大耗时 | 219.32 ms |
| 重载3次 | 2151.10 / 2176.98 / 2285.51 ms |
| JSON体积 | 5.992 MiB |
| 新快照保留的 Python 分配 | 29.76 MiB |
| 重载期间 Python 分配峰值 | 67.52 MiB |

内存使用 tracemalloc，在旧快照建好后开始采样，排除旧快照既有内存及解释器本身，不能作为进程总 RSS。

## 分解与复测稳定性

无 profiler 的独立顺序执行，30次中位数：全站过滤9.311 ms；单设备过滤2.888 ms；SQLite绑定查询0.444 ms；一页JSON编码0.584 ms。它们不含10并发请求的排队、线程调度、HTTP和客户端解码。

同进程 TCP 的两次结果 p95 为216.41 /171.79 ms，独立进程185.62 ms；因此不能将超时简单归因于共享 TestClient transport。宿主机负载和线程排队仍有影响。

cProfile 对40次交替查询计0.558s（profiler本身会显著增加耗时）：深复制累计0.273s约49%；名称筛选与casefold累计0.166s约30%；大候选集成员过滤0.058s约10%。

单次重载在 profiler 下7.077s：validate_snapshot6.720s、深复制2.893s、normalize_legacy_point2.346s、reject_relations1.726s、_walk1.536s。累计时间相互包含，不能相加；普通重载见上表。

## 已实施优化

1. `bound=false` 时直接从已有候选集排除绑定ID，避免先构造全量10000个ID集合；没有绑定时省略此过滤。
2. 加载索引时预计算名称casefold，查询直接匹配。
3. 用仅处理JSON dict/list和不可变标量的复制函数降低分页复制成本，同时保留返回值隔离测试。
4. 校验已深复制整个快照之后，内部旧字段规范化不再逐点深复制或重复递归检查；对外函数仍严格校验，不能通过删校验换性能。
5. 优化后使用相同脚本和数据重测，并保留失败结果，不选择性报告最好一次。

原始结果：`point-archive-api-arm64-20260917.json`。初次诊断时未改应用；随后经任务负责人授权实施下列优化。


## 优化后最终结果

在保持相同数据、字段、路由、筛选、10并发和50条分页的条件下，已实施：绑定排除直接作用已有候选集；名称casefold在加载时预计算；全站名称扫描使用顺序化 `(folded_name, row)` 索引；仅对已验证JSON容器执行安全递归复制；legacy内部复用一次校验与复制；关系键集合移出递归函数。**没有增加查询结果缓存，也没有减少请求返回字段。**

| 最终指标 | 结果 | 结论 |
|---|---:|---|
| 稳定阶段 API 中位数 / p95 / 最大 | 49.88 / 65.28 / 72.33 ms | p95 ≤100 ms通过 |
| 预热10请求最大 | 116.68 ms | 冷启动不满足100 ms，单独披露 |
| 重载3次 | 1408.95 /1155.09 /1147.99 ms | 均 ≤2 s |
| 保留分配 / 重载峰值 | 31.46 /67.53 MiB | 样本内存目标通过 |
| 全站查询 / 单设备查询中位数 | 1.819 /0.604 ms | 仅服务内查询核心 |
| SQLite查询 / JSON编码中位数 | 0.441 /0.607 ms | 单独组件测量 |

保留中间失败结果：第一轮优化后p95为119.34 ms，进一步消除全站扫描双字典查找后达到最终65.28 ms。原始最终结果：`point-archive-api-arm64-20260917-optimized.json`。

最后一次完整后端回归：**177 passed，17 subtests passed，12.04s**；4条既有依赖弃用警告。新增嵌套容器隔离、绑定排除候选集、名称索引更新回归。服务器原始输出保存至 `/home/hxzh/fms-point-archive-dev/full-regression-final.log`。

结果仅支持此隔离样本的稳定阶段门槛；真实绑定规模、真实鉴权、外部网络和现场设备仍需现场数据复验。
