## 1. 需求确认书

### 1.1 目标

在 Straitbot FMS 中新增 **机器人仿真页面**（路由 `/simulation`），用 Three.js 渲染一台**挂轨（轨道）机器人**的 3D 场景；通过 **后端 Python TCP/WebSocket 桥接**，使整个仿真对外表现为**一台真实的轨道机器人**——外部上位机可按《机器人控制板通信协议 V2.0》连接、下发运动/伸缩指令、读取 10Hz 状态上报。

### 1.2 已确认需求（用户逐条确认，含默认项）

| # | 需求点 | 结论 |
|---|--------|------|
| 1 | 仿真对象 | 轨道（挂轨）机器人，**单台** |
| 2 | 形态 | 轨道悬空于半空，机器人在轨道**下方**，**轮子在机器人顶部**贴合轨道；默认观察相机在机器人**下方** |

## 2. 总体架构

```
┌──────────────┐   TCP :50000    ┌─────────────────────────┐   WebSocket   ┌────────────────────────────┐
│  外部上位机    │◄──────────────►│       后端 Python        │◄─────────────►│      前端 Three.js 仿真页    │
│ (协议客户端)   │  二进制协议帧    │  TCP Server (asyncio)    │  二进制协议帧   │  /simulation                 │
│              │                │  WS Bridge (转发)        │               │  挂轨机器人运动模型 + 3D 场景 │
└──────────────┘                └─────────────────────────┘               └────────────────────────────┘
      ▲                                                                           ▲
      └── 上位机发 0x09 → 后端转发 → 前端驱动模型移动；前端 10Hz 组 0x0B → 后端转发 → 上位机收到状态
```

**数据流（两条）**

- **下行指令**（外部 → 仿真）：上位机 TCP 发帧 → 后端校验（可选）→ WS 推前端 → 前端解析 → 驱动运动学/伸缩杆；响应帧由前端组帧回传（见上行）。
- **上行状态**（仿真 → 外部）：
  - 周期：前端 10Hz 组 `0x0B 上传底盘运动状态`（含 X/Y/YAW/线速度/角速度）
  - 变化触发：伸缩杆状态变化时组 `0x0E 上传电机状态`
  - 前端 → WS → 后端 → TCP 写回上位机
  - 前端页面手动指令：**本地立即执行**，同时组 `0x09/0x0C` 帧经 WS/TCP 发出（对外可见）

**连接策略（第一版）**

- TCP 服务端常驻监听 50000；**单客户端策略**：新连接替换旧连接（对外表现简单可靠）。
- WS 与 TCP 解耦：前端 WS 断线重连；TCP 无客户端时后端保持监听，前端照常自运行。

## 3. 协议层设计（前后端共享规格）

### 3.1 帧结构（大端）

| 帧头 | 帧序号 | 消息长度 | 标记字 | 指令码 | 消息内容 | 校验码 | 帧尾 |
|---|---|---|---|---|---|---|---|
| 2B `0xA0AB` | 2B | 2B（=内容字节数） | 1B | 1B | 可变 | 2B | 1B `0xCD` |

- 帧序号：0~65535 自增；**响应帧序号 = 请求帧序号**。
- 标记字：bit7 = 0 正常模式（默认）；bit7 = 1 工程模式（透传保留）。
- 校验：`CRC16-CCITT`（poly `0x1021`，init `0xFFFF`），覆盖「帧头+帧序号+消息长度+标记字+指令码+消息内容」。
- 无特殊说明均**大端**。

### 3.2 指令实现表（第一版）

| 指令码 | 名称 | 方向 | 实现 |
|---|---|---|---|
| 0x06 | 心跳 | 下发 | 请求/响应内容均为空 |
| 0x09 | 底盘运动控制 | 下发 | 真实执行（见 3.3） |
| 0x0A | 获取底盘运动状态 | 下发 | 响应当前状态快照 |
| 0x0B | 上传底盘运动状态 | 上发 | 10Hz 主动上传（见 3.4） |
| 0x0C | 电机控制（伸缩杆） | 下发 | 真实执行（见 3.5） |
| 0x0E | 上传电机状态 | 上发 | 变化时/10Hz 上传 |
| 0x01 | 初始化控制板 | 下发 | 模拟响应（错误码 0 + 默认配置） |
| 0x02 | 获取控制板配置 | 下发 | 模拟响应（移动限速、伸缩限速/限高等默认值） |
| 0x04 | 获取版本号及 SN | 下发 | 模拟响应（V2.0.0 / SN 固定串） |
| 0x05 | 时间校准 | 下发 | 模拟响应（错误码 0） |

其余指令码：返回「错误码 = 不支持」响应（预留）。

### 3.3 0x09 底盘运动控制 [下发]

请求：`控制模式(1B) LinearX(2B) LinearY(2B) Angular(2B) TargetX(4B) TargetY(4B) TargetYaw(2B)` → 响应：`错误码(2B)=0`

**挂轨语义映射**（关键：轨道机器人是沿轨道的 1D 运动）：

| 协议字段 | 挂轨仿真语义 |
|---|---|
| 控制模式 | 0 停止 / 1 前进 / 2 后退 / 5 移动到指定位置 / 6 设定速度 / 10 初始化复位；**3/4 原地转向忽略**（轨道约束无转向） |
| LinearX | 沿轨道方向速度（mm/s），带符号（负=后退） |
| LinearY | 忽略（挂轨无侧向） |
| Angular | 忽略（偏航由轨道切线决定） |
| TargetX | **目标弧长坐标 s_target（mm）**，模式 5 使用 |
| TargetY / TargetYaw | 忽略 |

- 模式 5：`s_target = TargetX` 沿轨道移动到该弧长位置。
- 模式 10：弧长归零（回到轨道原点）→ 状态 3 初始化中 → 空闲。
- 模式 6：设定当前限速为 LinearX 绝对值。

### 3.4 0x0A / 0x0B 底盘运动状态

字段（0x0A 响应 / 0x0B 上传一致）：

| 字段 | 长度 | 取值 |
|---|---|---|
| （0x0A 先有错误码 2B） | — | 0 |
| 状态 | 1B | 0 空闲 / 1 运行中 / **2 已到达（瞬态）** / 3 初始化中 |
| 模式 | 1B | 仿真固定 2（嵌入式控制），收到指令后保持 2 |
| X | 4B 有符号 | 沿轨道弧长位置（mm），即 `s` |
| Y | 4B 有符号 | 固定 0（挂轨无侧向） |
| YAW | 2B 有符号 | 轨道切线方位角 ×10（°），左正右负 |
| LinearX | 2B 有符号 | 当前沿轨速度 mm/s |
| LinearY | 2B | 0 |
| Angular | 2B | 0（轨道约束） |

- 0x0B 上传策略：状态/模式变化 → 立即上传一次；速度/位置变化 → **10Hz 连续上传**，直到数据稳定。

### 3.5 0x0C / 0x0D / 0x0E 伸缩杆（电机）

- 电机 ID 约定：**1 = 伸缩杆升降电机**。
- 0x0C 请求：`电机ID(1B) 控制模式(1B) 速度(2B) 坐标(4B)` → 响应 `错误码(2B)=0`
  - 控制模式：0 停止 / 1 正转（升）/ 2 反转（降）/ **3 指定坐标（目标高度 mm）** / 4 复位（回零）/ 6 设定速度
- 0x0D 获取指定电机状态：响应含当前速度、**当前坐标（高度 mm）**、状态字、错误码、电流、温度（仿真给默认值）。
- 0x0E 上传电机状态：状态变化立即上传；速度/高度变化 **10Hz** 上传。

### 3.6 帧示例

`0x09 停止`（seq=1）：
```
A0 AB | 00 01 | 00 07 | 00 | 09 | 00 00 00 00 00 00 00 00 00 00 00 00 00 00 | <CRC16> | CD
```
（消息内容 7 字节：模式 0 + LinearX 0 + LinearY 0 + Angular 0，TargetX/Y/Yaw 为 0 即不移动；CRC 覆盖到内容末尾。）

## 4. 后端设计（Python / FastAPI / asyncio）

### 4.1 目录与文件

```
backend/app/simulation/
├── __init__.py
├── protocol.py        # 帧编解码 + CRC16-CCITT（Python 版，与前端同规格；主要透传）
├── bridge.py          # TCP Server(asyncio) + WS 客户端管理 + 双向转发
└── router.py          # /ws/simulation WebSocket + /api/simulation/status
backend/app/main.py    # 挂载 simulation router + lifespan 启停 TCP Server
backend/app/config.py  # SIM_TCP_HOST=0.0.0.0, SIM_TCP_PORT=50000
backend/tests/test_simulation.py   # 单测：CRC/帧/转发回环
```

### 4.2 TCP Server（bridge.py）

- `asyncio.start_server(handle_client, host, port)` 常驻监听 50000。
- `handle_client(reader, writer)`：
  - 新连接 → 替换当前客户端（旧连接关闭，`tcp_connected=true`）→ 通知 WS 端（连接状态变更消息）。
  - 读循环：`await reader.read(4096)`，**按帧边界切包**（缓冲 + 按帧头 `0xA0AB` / 帧尾 `0xCD` / 长度字段拆分，容忍粘包/半包）→ 完整帧推入 WS 发送队列。
  - 写循环：从「前端→TCP」队列取帧 → `writer.write` 发给上位机。
  - 断开 → `tcp_connected=false` → 通知 WS。

### 4.3 WS Bridge（/ws/simulation）

- `@router.websocket("/ws/simulation")`：
  - 前端连入后注册为 `ws_client`；断开自动清除（前端断线重连）。
  - **后端收到 WS 二进制帧**（前端组好的响应/上传帧）→ 若 TCP 有客户端 → 原样写回；否则丢弃（记录日志）。
  - **TCP 收到帧** → `await ws.send_bytes(frame)` 推前端。
- 帧转发原则：**后端不改帧内容**（透传），仅在两端缺连接时按策略处理（TCP 无客户端时丢弃下行转发；WS 无前端时丢弃 TCP 转发）。

### 4.4 状态端点

- `GET /api/simulation/status` → `{ tcp_connected, ws_connected, tcp_port, uptime }`，前端轮询（或 WS 内推送）。

### 4.5 生命周期

- `main.py` lifespan：`init_simulation_bridge()` 启动 TCP server；关闭时 `await bridge.close()`（关 TCP、清 WS）。
- 配置走 `app/config.py`（可被环境变量覆盖）。

## 5. 前端设计（React + Three.js + TS）

### 5.1 目录与文件

```
frontend/src/
├── views/RobotSimulation.tsx     # 页面：Three 容器 + Semi UI 面板 + WS 状态
├── simulation/
│   ├── protocol.ts               # 帧编解码（DataView 大端）+ CRC16-CCITT 表驱动
│   ├── track.ts                  # 矩形环轨道曲线：弧长 s → 3D 位置/切线/法线
│   ├── robot.ts                  # 机器人运动学（1D 弧长 + 伸缩杆）+ 状态机
│   ├── scene.ts                  # Three.js 场景/环境/机器人拼装/渲染循环/Raycaster
│   └── ws.ts                     # WebSocket 客户端（连接/重连/二进制收发）
├── router/index.tsx              # 注册 /simulation 路由 + 侧边菜单
└── api/simulation.ts             # GET /api/simulation/status
```

### 5.2 轨道模型（track.ts，矩形环）

- 参数（可配置常量）：直段长 `L=6m`、弯道半径 `R=1.5m`、悬挂高度 `H=2.5m`、轨道管径 `0.06m`。
- 参数化：下直段 → 右半圆弧 → 上直段 → 左半圆弧（顺时针闭合）。
- 总弧长 `S = 2L + πR×2`；映射 `s(mm) → P(s)`（位置）、`T(s)`（切线单位向量）、`N(s)`（轨道平面法线，向上）。
- 轨道几何：`TubeGeometry`（CatmullRom 或手工样条曲线）生成管道；支吊架（立柱 + 顶部横梁 + 吊杆）程序化摆放。
- 提供 `sample(s)` 用于机器人定位与轮子贴合。

### 5.3 机器人程序化拼装（scene.ts / robot.ts）

**视觉层级（自顶向下）**：
1. **轨道轮组**：车体顶部 4 个轮（圆柱+轴），贴合轨道下沿；动画：轮子自转角 `ω = v / r`。
2. **车体**：主机箱（长方体，含指示灯/标识面）、吊架（连接轮组与箱体）。
3. **伸缩杆**：车体下方垂直滑杆（几何体沿 Y 缩放/位移模拟升降，高度 `h` mm）。
4. **巡检相机**：伸缩杆末端朝下的小相机模型（盒体 + 镜头），即"相机在机器人下方"。

**挂轨姿态**：机器人位置 = `P(s)`，朝向 = 轨道切线 `T(s)`（绕世界 Y 校正），轮轴对齐轨道截面法线；机器人整体随轨道曲率自然转向。

### 5.4 运动学（robot.ts）

- 状态：`s(mm)`、`v(mm/s)`、`s_target`、`a(mm/s²)`（梯形加减速，默认 `a=200`）、到位阈值 `ε=10mm`。
- 控制：
  - 模式 0 停止：减速到 0。
  - 模式 1/2：按 LinearX 设定速度恒速（带加减速）。
  - 模式 5：目标 `s_target=TargetX`，梯形速度曲线移动，`|s-s_target|<ε` → **状态=2 已到达（保持 1 个上传周期）→ 0 空闲**。
  - 模式 10：`s=0` 复位，经过状态 3 初始化中。
- 限位：`s ∈ [0, S)` 环形取模（矩形环闭合，越过 0 点绕圈）；速度上限 `V_MAX=1500mm/s`。
- 伸缩杆：`h`、`h_target`、`v_h`（默认 100mm/s），模式 3 移动到位、模式 4 回零；状态/速度/高度随 0x0E 上报。

### 5.5 3D 场景（scene.ts）

- 环境：地板（平面 + GridHelper）、厂房立柱、顶部横梁、环境光 + 方向光（可选阴影）。
- 相机：`PerspectiveCamera` 默认置于**机器人下方**（相对机器人 `[0, -0.9, 1.8]`，仰视），`OrbitControls`（`target` 跟随机器人弧长位置），支持旋转/缩放/平移。
- 渲染循环：`requestAnimationFrame`；每帧更新机器人位姿 + 轮子滚动 + 伸缩杆高度；**10Hz** 节流组 `0x0B` 帧。
- 点选：`Raycaster` + 机器人 Mesh 拾取 → 高亮描边 → 状态面板。

### 5.6 页面 UI（RobotSimulation.tsx，Semi UI）

- 顶部：页面标题 + 连接状态 Tag（WS：已连接/重连中；TCP：外部已连接/等待连接，来自 status 轮询）。
- 中部：Three.js canvas（占满）。
- 右侧/底部面板：
  - **机器人状态**：弧长 X(mm)、YAW(°)、速度、模式、状态（空闲/运行/已到达/初始化）、伸缩杆高度、SN/版本（模拟）。
  - **指令面板**：速度设定（mm/s）、前进 / 后退 / 停止、移动到目标位置（弧长 mm）、伸缩杆目标高度（mm）；点击 → `robot.applyCommand(...)` + 组 `0x09/0x0C` 帧经 WS 发送。
- 选中机器人后状态面板自动弹出/高亮。

### 5.7 WebSocket 客户端（ws.ts）

- `ws://{host}/ws/simulation`，二进制模式。
- 收：`onmessage` 二进制 → `decodeFrame` → 指令分发（0x09 → 运动；0x0C → 伸缩；0x06/0x0A → 立即组响应帧回发；0x01/0x02/0x04/0x05 → 模拟响应回发）。
- 发：`sendFrame(seq, cmd, payload)`（帧序号前端维护）。
- 断线重连：指数退避（1s→2s→4s…上限 10s），重连成功恢复转发。
- 状态回调 → 页面顶部 Tag。

## 6. 协议编解码要点（前后端同规格）

```
CRC16-CCITT: poly=0x1021, init=0xFFFF, 无反射；查表或逐位实现，两端一致
encodeFrame(seq, cmd, payload) -> Uint8Array
decodeFrame(buf) -> { seq, cmd, payload } | null   // 校验：帧头 0xA0AB、长度匹配、CRC、帧尾 0xCD
帧序号管理：前端（仿真）维护；响应帧复用请求序号
```

## 8. 验证方案

1. **后端单测**（pytest）：CRC 已知向量、帧编解码边界（半包/粘包）、TCP↔WS 转发回环。
2. **前端**：`tsc` 0 错误；浏览器运行 `/simulation`。
3. **端到端**（模拟上位机，python 脚本）：
   - 连接 `127.0.0.1:50000` → 发 `0x06 心跳` → 收响应。
   - 发 `0x09 模式5 TargetX=3000mm` → 浏览器中机器人沿轨道移动 → 持续收 `0x0B`（10Hz，X 递增 → 到位 → 状态 2 → 0）。
   - 发 `0x0C 电机1 模式3 坐标=500mm` → 伸缩杆下降 → 收 `0x0E` 高度变化。
   - 无外部连接：页面指令本地生效，状态面板正常。
4. **对外一致性**：任何时刻上位机看到的 X/Y/速度/高度都与页面一致（同一状态源）。

## 9. 待确认/风险

- TCP 帧按「帧头+长度+帧尾」拆包：若上位机实现不严格（如无帧尾），需在联调阶段加容错（按帧头重同步）。
- 模式 3/4（原地转向）对挂轨无意义：收到时返回错误码 0 但不动作（记录日志），语义上保留协议兼容。
- 多客户端：第一版单客户端（新连接替换旧），如上位机存在多连接需求，第二版扩展为「多客户端 + 指定 ID 路由」。
