Sm 内核：一个 tick 内的信号流

emit(signal)
周期/超时/外部信号
→
acts FIFO 队列
exit/enter 也入队
→
applyAct()
每 tick 只 pop 1 个
→
behXxx()：一串独立 if(st==…)
非 elif，迁移后继续 fall-through
→
setState()
exit 中再迁移直接 raise
后果：① 同 tick 内可能用“新状态 + 旧信号”连续穿越多个状态（级联迁移）；② 一 tick 多信号被积压，时序不确定；③ stop() 只发 exit、不清 st，signalMove 靠 st is None 判启动 → 子机无法二次激活。

问题分级

级别 问题
P0无法编译运行：中文逗号(L395/398)、TS 语法 [] as SmTimeoutSignal[](L124)、broadcastSignal 缺冒号(L327)、si/moevSt 未定义、缩进错误；全项目零引用、零测试。
P1内核：if 非 elif 级联迁移；单信号槽 + FIFO 每 tick 一个导致信号积压；setTimeout 不随状态切换清理且微挪分支每 tick 新增（泄漏）；子机 stop 后不可重入；子机结束无 complete 回连。
P1集成：async/sync 边界混乱（await 同步函数、缺 import asyncio）；动作未走 BoardSrv/RobotCtrl 命令队列；与已完成的前端 FsmEditor（.fsm.json：状态机/状态/信号迁移/状态机激活三 pin）是两套模型，未打通。
P2建模：模块级全局单例 robotState/mainSm（不支持多机、难测试）；状态类用类注解当字段（访问即 AttributeError）；pydantic 字段写成赋值；中文命名/拼写错误/空状态名；无日志与并发保护。
可取的方向：分层并行状态机（main + 充/层/巡子机）、信号队列 + 动作对象、周期 tick 信号 + 带状态匹配的超时、enter/exit 成对与进入重置计时——概念选型正确，业务流程拆解完整。建议把内核改造成由 FsmSpec 解释执行的声明式运行时，而非继续在 behXxx 里堆 if/else。
