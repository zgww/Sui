# 多地图、多楼层巡检计划

## 业务与协议边界

沿用 `INSPECTION-DOWNSHIFT.md` 的旧平台任务配置、测点绑定和 cmd=100–106 映射。FMS 负责计划、排期、分段编排和执行审计，机器人执行每段航点动作；Java/Vue 旧架构不修改。

旧 `Common/.../Cmd100DTO.java` 的 `substationMapsId` 是旧平台地图标识，新版设备文档未定义该字段，FMS 不将本地数据库地图主键作为设备换图参数下发。现有 FMS 未实现可验证的自动乘梯、换图和重定位执行链。因此每段限定一张地图和一个有效楼层，分别生成 cmd=100，不能将不同地图坐标合并下发。楼层取航点覆盖值，否则继承地图楼层，均为空时取 0。

跨段采用明确的到达确认：上一段完成 → `waiting_transition` → 操作员确认已到达并定位到目标地图/楼层 → 发送下一段。每日/每周调度只自动发起首段；自动跨楼层导航尚未设备联调，不包含在本实现中。

## 配置与接口

- `stages: [{map_pk, floor, point_ids}]` 按数组顺序执行，最多 100 段、合计 10,000 个不同测点。允许同一地图不同楼层、相同测点在不同段重复巡检。
- 保留 `map_pk` 为首段地图、`point_ids` 为有序去重并集，兼容旧单地图调用。`stages=NULL` 的旧计划继续原逻辑；编辑成多段时必须明确楼层。
- `GET /api/inspection-plans/options/floors?robot_pk=…` 返回当前机器人地图/楼层；测点选项接口增加 `floor` 过滤。
- 保存、启用与执行均校验机器人、地图、楼层、测点状态、绑定动作。被任一段引用的地图不能删除或覆盖。
- `POST /api/inspection-plans/executions/{id}/continue` 接收 `robot_pk`、当前 `stage_index`、`confirmed=true`，仅工程师可调用。重复确认返回当前进度，不重复下发。

## 执行一致性

整条路线在首段下发前编译并保存不可变快照。后续编辑计划、航点坐标或绑定不改变已开始的路线。执行记录增加 `route`、`stage_index`；每段有独立协议 ID，首段使用执行 ID，后续为 `-s2`、`-s3`。状态、结果和控制命令按当前分段关联；迟到的旧分段状态不推进路线。

机器人租约跨段保留。发送前持久化分段占用，超时保持 `unknown`，不自动重发；确认取消、最后一段完成或人工核对空闲关闭后释放。重启恢复等待状态，不自动确认跨段。

## 界面

列表展示路线顺序、测点数和调度。编辑器左侧分段导航、右侧楼层测点选择，支持添加、移除、上下移和跨页勾选；下方集中设置手动/单次/每日/每周调度。执行历史展示当前段及继续操作。

设计沿用运维界面：深蓝 `#19344c`、操作蓝 `#266fb8`、浅蓝 `#eef5fc`、灰蓝 `#718397`、边线 `#dfe7ef`。中文使用现有系统字体；顺序编号用等宽字体。编号表达真实执行顺序，不添加装饰性指标卡。

## 隔离 Demo

入口脚本：`backend/scripts/inspection_demo.py`。仅在 `FMS_INSPECTION_DEMO=1` 下启动，已有非 Demo 数据库会拒绝加载；必须使用独立空数据卷。挂载脚本目录到 `PYTHONPATH` 后运行 `python -m uvicorn inspection_demo:app --host 0.0.0.0 --port 8000`。

内置 2 个模拟机器人、3 张地图、4 个楼层分段、24 个航点、48 个动作和 96 个测点，提供全站、配电楼每日、主控楼与地下设备间每周三套示例。所有 `robot_api.call` 都在独立入口被模拟，不连接真实设备。默认仅手动计划启用，可在 Demo 中启用定时计划查看日历。

## 验证与回退

执行 `python -m pytest tests -q` 和前端 `npm run build`。回归覆盖楼层继承/覆盖、地图范围、重复外部航点 ID 的分段隔离、不可变快照、重复确认、错误机器人、迟到上报、权限、断线和旧计划往返。

SQLite 启动时自动增加可空 JSON 字段和 `stage_index` 默认值 0，不删除已有数据。发布前停止后端并备份数据和 Compose 配置。回退旧版前必须结束分段执行并恢复发布前数据库/配置；不能让旧版忽略新计划的后续分段后继续运行。保留发布后的数据副本，避免丢失期间新增内容。
